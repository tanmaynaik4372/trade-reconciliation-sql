# Trade Reconciliation & Settlement Monitoring (SQL)

A small SQL project that mimics a middle/back-office control: matching internally captured trades against
counterparty confirmations, then tracking which trades fail to settle and who is responsible.

**Data is fully synthetic** (2,000 trades across Equities, Bonds, FX and Derivatives, 1 Jul - 30 Sep 2026,
generated by `generate_data.py` with a fixed seed). Breaks and settlement fails are injected on purpose so the
analysis has something to find. No real market or client data is used.

## Trade lifecycle covered
| Stage | Table | Question answered |
|---|---|---|
| Trade capture (front office) | `trades` | What did we book? |
| Confirmation / matching (middle office) | `confirmations` | Does the counterparty agree on price, quantity and settle date? |
| Settlement (back office) | `settlements` | Did the trade settle on time? |

## How to run
```bash
python generate_data.py        # builds trades.db using schema.sql
sqlite3 trades.db < queries.sql
```

## Queries (`queries.sql`)
1. Trades with no counterparty confirmation
2. Reconciliation breaks, classified as PRICE / QUANTITY / SETTLE DATE
3. Break rate by asset class (CTE)
4. Settlement fail rate and failed notional by counterparty
5. Ageing buckets for failed trades
6. Counterparty ranking within each asset class (window function `RANK() OVER`)

## Findings (synthetic data)
- 126 of 2,000 trades (6.3%) were unconfirmed or had a price, quantity or settle-date break.
- Equities had the highest break rate (7.35%); FX the lowest (4.98%).
- Corvus Markets had a 7.26% settlement fail rate against 0.82% - 2.17% for every other counterparty,
  and the highest failed notional.
- 53 trades failed to settle; many are 30+ days overdue and would need escalation.

## Suggested next steps
Tolerance rules for price breaks (e.g. ignore differences under 0.1%), a Power BI or Tableau dashboard on top,
and a small Python script to export a daily breaks report.
